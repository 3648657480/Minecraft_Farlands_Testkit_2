## 三、渲染架构的关键决定（改代码前必须知道）

1. **本地帧**：网格跑局部坐标 `local = worldSection - base`，base 是 2^22 段的整数倍
   （`WideRenderBase`）。世界身份只在 `SectionKey` 里。
2. **段原点**：`terrain.vsh` 自己减相机，所以 `ChunkPosition` 传**世界原点**（≤2^31）；
   本地帧建立后走「整帧本地空间」：`GlobalSettingsFarCameraMixin` 把传给 uniform 的相机
   换成它的小数部分（`CameraBlockPos` 变成 0），段原点改传 `world - cameraBlock`。
3. **剔除盒必须用世界坐标**：视锥是世界空间。把它改成相机相对会出现「静止正常、一转视角
   全消失」。
4. **编译入口只有 `LevelExtractor.allChanged()` 可靠**。用 `ClientLevel.setSectionRangeDirty`
   替代会导致「一个段都不编译」（已验证，见 2026-11-13 教训）。
5. **`STRICT_BAND`**（`farlands.client.strictBand`，默认 true）只应门控「Y 分页窗口」相关
   的 hack；不能门控「可见集重填」——fork 绕过了 `SectionOcclusionGraph.update`，没人重填
   就会整屏空。

## 四、生产化改动（实机零 JVM 参数即可运行）

- `G2Mod.onInitialize` 固化 2^53 成功配方：`farlands.y.window` / `farlands.follow` /
  `farlands.diag.clientWideChunk` 默认 `true`（仅在未显式设置时写入）
- 客户端 `WideClientBridge` 默认解析宽区块（`farlands.far.clientWide`，默认 true）
- 服务端 `ServerFarStreamMixin`：玩家进入远域时启动一次 `FarChunkFeeder.startFollow`
  （半径 `farlands.far.pushRadius`，默认 4）
- 方块实体坐标在 NBT 里额外写 `farlands$x/y/z`（long，仅超出 int 时）
- 远域光照护栏：`FarLightMode` 标志 + `LayerLightSectionStorageMixin`（远域直接按全亮）

## 五、为什么之前会「runClient 好、实机全是问题」

已逐项验证**不是**环境玄学：

- fork jar 与 loom 开发 jar：10952 个 class **CRC 逐字节一致**
- mixin：两侧 `-Dmixin.debug.verbose=true`，共同加载的 53 个目标类**注入集合 0 缺失**
- PCL 注入的 GC 参数（`+UseG1GC / MaxGCPauseMillis=50 / G1HeapRegionSize=32M /
  MaxHeapFreeRatio=40 / +UseCompactObjectHeaders`）套到 runClient：生成速率 25→28 块/秒，无影响
- `farlands.*` 参数两侧一致；JDK 都是 25.0.3；`isDevelopmentEnvironment` 无人使用

真正原因是**场景差异**：开发世界 `test7_01` 的远区块是 11-02 预生成的（只读不生成）；
实机是新世界现场生成；再叠加「建立帧时三连全量标脏」和「推流半径 5」。

## 八、下一步（按顺序，命令级）

**第 1 步：判定「实机慢」是否已解决**

在同一坐标 `2147483647 70 0` 分别跑：

```powershell
# 开发形态
.\gradlew.bat :mod:runClient --no-daemon -Dfarlands.autotest=true -Dfarlands.autotest.world=test7_01 `
  -Dfarlands.autotest.directTp=true -Dfarlands.autotest.spectator=true `
  -Dfarlands.autotest.x=2147483647 -Dfarlands.autotest.y=70 -Dfarlands.autotest.z=0 `
  -Dfarlands.diag.render=true

# 安装形态
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\prod-client.ps1 `
  -JvmArgs "-Dfarlands.autotest=true;-Dfarlands.autotest.openWorld=true;-Dfarlands.autotest.world=新的世界 (1);-Dfarlands.autotest.directTp=true;-Dfarlands.autotest.spectator=true;-Dfarlands.autotest.x=2147483647;-Dfarlands.autotest.y=70;-Dfarlands.autotest.z=0;-Dfarlands.diag.render=true"
```

比较两者的 `store=` 增长速度与 `mesh` 收敛速度。一致 → 「实机慢」随半径 4 + 去掉三连标脏
已解决；不一致 → 差异只剩「mod 打包形态 / Knot 启动」两项，继续用 prod-client 二分
（候选实验：`-Dmixin.debug.export=true` 导出变换后的 class 逐字节比对）。
