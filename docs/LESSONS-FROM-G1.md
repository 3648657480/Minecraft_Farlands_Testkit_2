# G1 → G2 经验总结

> 权威红线见根目录 `AGENTS.md`（R7–R10 + 五条铁律）。本篇是 G1 结项时对**可迁移经验**的落档，
> 供 G2 开工前对齐认知。所有数值均为“本项目条件下的特定结果”（R10）。

---

## A. 机制层：Far Lands 到底是什么

1. Far Lands = **double 精度 + `PerlinNoise.wrap()` 失效**，是浮点数学，不是 bug。
2. **量化档固定、与种子无关**：2⁵³ → 2 格、2⁵⁵ → 8、2⁵⁶ → 16、2⁶³ → 2048。
3. **主噪声损毁点 = k0 = `1808764368955220493860864`**（1 ULP 突变、多种子一致、可复现，见 G1 EXPERIMENTS §8.3）。
4. **可见的“奶酪墙”在 epoch 边沿 `local ±2²⁷`**（真实坐标 = epoch ± 2²⁷），**不在 epoch 中心**（G1 EXPERIMENTS §8.4）。
5. “起点”是**瞬变点**（宽 1 ULP = 2.68e8 格）→ **没有可见边界**；经典“看得见的墙”是 32 位/int 边界，
   **64 位/double 的墙注定看不到**。
6. **肉眼起点随种子/epoch 浮动；阈值/桶固定** → 记录必须带 种子 + epoch + 管线。

---

## B. 工程层：G1 的架构边界 = G2 的起点

1. **epoch 路线（local 域）** 是 G1 核心：可玩、可研究；但**实体/渲染/tick 都在 local** →
   2⁵³ 以上的非地形精度现象**不发生** → 必须放弃（G2 走全链路宽化）。
2. **整数子系统要“全链路同船”** 真实坐标化（B 线 13 处）；半开 = 两套域互撕（宽化必须一起做）。
3. 容器 int→long 加宽了，但 **int 访问器保留回绕语义** → **consumer 必须逐个迁 `getLong`**（G2 的 W5）。
4. **64 位打包 key 是硬墙**（SectionPos 27bit / ChunkPos 32+32）→ 需要 **128 位 key**（G2 的 W4）。

---

## C. 诊断/验证层：G1 最痛的坑

1. **指标必须匹配现象**：`topY` 只抓“主噪声损毁”，**抓不到弱层/奶酪墙** → 用错指标会误判“没有墙”。
2. **客户端 ≠ 服务端**：必须两端对齐（截图 / F3）才能定案；“on my PC”要主动排除。
3. **现象对不上，先去测 / 复现，别用文字糊**（结论必须有数据/截图）。
4. 一次只改一个变量；报错先复现；**期望先写、结果后核**。

---

## D. 发布/工具层：玩家侧

1. 单机 + 自备客户端 jar；**不分发任何 Minecraft 文件**。
2. **必须禁用 / 移除 Fabric API**（与补丁 mixin 冲突，会崩）。
3. **Java 21+**（默认 `1.8` → `UnsupportedClassVersionError`）。
4. 关闭启动器文件校验；建议**离线账号**；**替换的是版本 jar**。
5. patcher 要：**原子写 + 输入校验 + `ZipFile`（保真）+ 默认全套补丁 + 一键 `patch.bat`**。
6. **一个自包含分发包**（jar + docs + INSTALL），别让用户编译 / 下 3 个文件。
7. 版本只认仓库根 `VERSION`；日志 / 构建产物不进公开仓库。

---

## E. 沟通层：血的教训

1. **别把话说满**（“一定固定 / 不会浮动”）；讲清“**什么固定、什么浮动**”。
2. **先拿数据 / 截图再下结论**。
3. 用户说“找不到 / 不一样” → **先怀疑自己的指标 / 位置**，别先辩解。
